# Nomor antrean, pemanggil loket & mLITE/SIMRS

- Tombol "🔊 Panggil" di `/admin/dashboard` memanggil `callVisitAction` → tabel `queue_calls` (migration `0012`, kolom `loket`, `is_recall`). Nomor loket dipilih admin ("Loket saya", localStorage `admin-loket`).
- Tiket Pasien Baru `/kiosk` (BPJS & Umum; lihat bagian Kiosk) juga dibuat di SIMRS `mlite_antrian_loket` (`/kiosk2` tidak: `skipMlite`, nomor app) sesuai prefix layanan (`services.queue_prefix`, migration `0015`, diatur di Pengaturan Aplikasi admin "Prefix nomor antrean"; konstanta `app/lib/queue-prefix.ts`, default BPJS/Umum A, CS B): A → type `Loket` (`createGeneralLoketQueue(1)`), B → type `CS` (`createGeneralLoketQueue(2)`). Hanya `MLITE_SERVICE_CODES` (registrasi, poli_umum, customer_service) yang bisa diatur. mLITE menyimpan angka saja (`noantrian` = `1`); tautan `visits.notes` = `mlite:<kd>:A1` (A/B = type mLITE). Nomor di tiket tetap huruf layanan (lihat bawah), bukan A/B. Gagal SIMRS → tiket tetap dibuat dengan nomor app. Tabel mLITE milik SIMRS: jangan dibuat/diubah strukturnya.
- Pemanggil loket di dashboard (`LoketCaller`, satu kartu per layanan kiosk = `getAllServices` (aktif, tanpa `poli_*` selain `poli_umum`, urut id), label dari `services.label`; layanan tanpa tautan mLITE: nomor app, tanpa Simpan RM; `callLoketAction` menolak kode di luar daftar itu `SERVICE_INVALID`; type `loket`/`cs` dari huruf nomor): Berikutnya / Lompat → (pilih tiket + insert di bawah `withNamedLock('apm_queue_call')`, satu lock untuk semua loket & tombol 🔊; panggilan mLITE setelah lock dilepas) `queue_calls` + mLITE `anjungan/loket?show=panggil_<loket|cs>&loket=L` (end_time nomor sebelumnya) + `&antrian=N&reset=L` (counter) + `anjungan/setpanggil` (status 1, loket); Panggil Ulang → hanya `setpanggil`. Kartu juga punya "✓ Layani" (tiket terakhir masih `waiting`, `serveAction`) dan "✓ Selesai dilayani" (sudah `served`, panggilan terakhir belum `finished_at`, `finishVisitAction`; tiket tertaut mLITE juga ditutup di SIMRS DB: `finishMliteQueue` → `status 2` + `end_time` (bila masih `00:00:00`) by `kd`; gagal → `mliteOk: false`), sama seperti daftar kunjungan; `current.finished` dari `queue_calls.finished_at` panggilan terakhir. Simpan RM → `anjungan/simpannorm` (RM wajib 6 digit, dicek baca-balik by `kd`) lalu visit `served`. Skema: github.com/basoro/mlite `plugins/anjungan` (Site.php, Admin.php). Kode di `app/server/mlite-loket.ts`, `functions/loket-caller.ts`.
- Baris mLITE Pasien Baru (`createGeneralLoketQueue`) selalu langsung ke DB SIMRS (`SIMRS_DB_*`, tanpa HTTP ke web mLITE): di bawah `GET_LOCK('apm_general_loket_queue')` hitung `MAX(noantrian)` hari ini per type (Loket/CS) + 1 (nomor mLITE, beda dari nomor tiket), lalu `directInsertQueue` (INSERT sama dengan mLITE `simpanloket`/`simpancs`, `kd` dari `insertId`).
- Semua penulisan mLITE (nomor baru, panggil, Simpan RM, selesai) langsung ke DB SIMRS `SIMRS_DB_*` (SQL meniru PHP mLITE, `app/server/mlite-direct.ts`), tanpa HTTP ke web mLITE: endpoint HTTP mLITE (`MLITE_GENERAL_PATIENT_URL`) menulis ke DB lain sehingga panggilan tidak tercatat. Status mLITE: `0` menunggu, `1` dipanggil (+`loket`, `setpanggil`), `2` selesai (`panggilselesai`; app: "Selesai dilayani" → `status 2` + `end_time`).
- Nomor antrean disimpan permanen di `visits.queue_number` (migration `0016`) saat `createVisit`. Semua tiket online = huruf per layanan + counter harian app, sama untuk pasien baru & lama (`SERVICE_QUEUE_LETTERS` di `app/lib/queue-prefix.ts`, daftar tampil di Pengaturan "Prefix nomor antrean"): Poli Umum D, BPJS `registrasi` B, CS C, Lab L, Vaksinasi V, Surat Keterangan S, IGD I, Layanan Lainnya LL, lainnya P. Kiosk Loket 1 → `poli_umum` (D), Loket 2 → `customer_service` (C); pratinjau kiosk = nomor app berikutnya. Pasien baru tetap dapat baris mLITE (type Loket/CS dari setting "Antrean SIMRS pasien baru" `services.queue_prefix` A/B, atau pilihan loket) dengan nomor mLITE sendiri (`noantrian`), hanya ditautkan lewat `visits.notes` `mlite:<kd>:A7`; huruf A/B di note = type mLITE, bukan nomor tiket. Gagal SIMRS → tiket tetap nomor app tanpa tautan. `insertWithAppQueueNumber`: `withNamedLock('apm_queue_<huruf>')` + `lastAppQueueNumber` (cocok huruf persis via `REGEXP ^<huruf>[0-9]+$`, supaya L tidak ikut LL) + insert autocommit; jangan pakai GET_LOCK di dalam `transaction`. Offline → `O<perangkat>-001` (kode perangkat 1–99 dari `/kiosk2?device=N`, localStorage `kiosk2_device`; format lama `O001` masih diterima sync), di-insert lewat `insertWithFixedQueueNumber` (tanpa `ON DUPLICATE KEY UPDATE`); id sama → no-op, nomor dipakai visit lain → `QUEUE_NUMBER_TAKEN` (sync offline membuang tiket itu + log). `getDailyQueueNumber` memakai `queueNumber` bila ada (semua select visit wajib ikut `queueNumber: visits.queueNumber`). Unique key `uq_visits_queue_date_number` (migration `0017`). Pemanggil "Panggil nomor lain" terima huruf ganda (LL7). `markServed` = update bersyarat `status='waiting'`; Simpan RM cek status sebelum menulis ke mLITE (`VISIT_NOT_WAITING`).
