# Display TV (`/display`, `/display-kamar`, `/display-poli`, `/display-poli-mata`)

- `/display` (tanpa login, `app/components/display/`) polling `getDisplayAction({ afterId })` tiap 2 detik; panggilan baru diputar FIFO: bel Web Audio, overlay, suara 2× (`app/lib/announce.ts`: ResponsiveVoice "Indonesian Female"; key `RESPONSIVEVOICE_KEY`/`VITE_RESPONSIVEVOICE_KEY` dibaca server saat runtime lewat `getDisplayAction.responsiveVoiceKey`, bukan saat build; ResponsiveVoice tetap suara utama; yang tidak mulai dalam 8 detik (`RV_START_TIMEOUT_MS`: tanpa suara Indonesia bawaan, RV mengunduh MP3 per teks dari `getvoice.php`, ±1 detik, bisa lebih lama di jaringan klinik)/error → `speechSynthesis` suara id-ID, utamakan suara offline (`localService`, mis. Windows "Microsoft Andika") daripada "Google Bahasa Indonesia" (online); `speechSynthesis.speak` diberi jeda 50 ms setelah `cancel()` (Chrome kadang mengabaikannya) dan utterance disimpan di variabel modul (onend hilang bila ter-GC); selama audio terkunci `speak` langsung pakai `speechSynthesis` karena `audio.play()` internal ResponsiveVoice melempar `NotAllowedError` tanpa catch). Selama audio terkunci (belum ada klik & tanpa flag autoplay) `DisplaySoundGate` memasang lapisan klik transparan layar penuh tanpa tulisan (klik di atas iframe YouTube tidak sampai ke halaman).
- Video kiri: setting `display_youtube_playlist` (Pengaturan Aplikasi admin) berisi satu ID playlist, atau beberapa ID video 11 karakter dipisah koma (diputar berurutan & berulang: pindah video diatur `useYouTubePlayer` saat `ENDED` lewat `nextVideoId`, bukan param `playlist` YouTube yang memutar `videoId` dua kali). Judul video/playlist tidak ditampilkan. Video mulai mute lalu unmute setelah audio diizinkan (`youtubeSource.ts`). Overlay video (judul, "SEDANG DIPUTAR", tombol audio, progress) hanya tampil saat mouse hover / fokus di area video (`group-hover` di `DisplayVideo`).
- Status loket di `/display` (`DisplayLoketList`): loket default `DISPLAY_DEFAULT_LOKETS` (`displayConfig.ts`, Loket 1 = Antrean A, Loket 2 = Antrean B) selalu tampil "TERSEDIA" sampai memanggil; loket lain muncul setelah panggilan pertama hari itu.
- Running text `/display` diawali jadwal sholat hari ini (`app/lib/prayer-times.ts`, dihitung lokal metode Kemenag: Subuh 20°, Isya 18°, Ashar Syafi'i, ihtiyat +2 menit dibulatkan ke atas; tanggal & UTC+8 dari `DISPLAY_TIMEZONE`/`DISPLAY_UTC_OFFSET`). Setting `app_settings.prayer_times` (JSON, migration `0018`, NULL = default Maros) diatur di Pengaturan (`PrayerTimesSettings`): tampil/sembunyi, preset Maros/Makassar/Gowa/Pangkep atau koordinat sendiri, nama tampil, koreksi menit per waktu (±30). Divalidasi `parsePrayerSettings`. Saat masuk waktu sholat (`usePrayerAlarm`, cek tiap 15 detik, jendela 2 menit, sekali per waktu per hari): masuk antrean yang sama dengan panggilan pasien (`useCallAnnouncer` `enqueuePrayer`, tidak saling potong) → jingle `public/sounds/prayer-announcement.mp3` (`playSound`, fallback `chime`) + splash `DisplayPrayerOverlay` + TTS `prayerAnnouncementText` (pitch 1.2, sekali) + video diredam. Tombol "🔊 Tes pengumuman di TV" (Pengaturan) → `testPrayerAnnouncementAction` → tes di memori server (`functions/display-test.ts`, hilang saat restart) → `getDisplayAction.test`; tiap `/display` yang terbuka memutar pengumuman sholat berikutnya sekali (tes sebelum halaman dibuka tidak diputar ulang). Tombol "🔊 Tes panggilan di TV" (`DisplayCallTest`, `testPatientCallAction`) lewat jalur yang sama (`kind: "call"`): contoh panggilan A001 "Tes Panggilan" ke Loket saya (id negatif), tidak ditulis ke `queue_calls`/mLITE.
- `/display-kamar` (publik, desain `design/DESIGN-DISPLAY-KAMAR.md`, pengganti SIMRS `webapps/bed7.php`): jadwal dokter hari ini (`jadwal`/`dokter`/`poliklinik`, `hari_kerja` dari tanggal WITA `hariKerja()`, bukan `DAYNAME()`) + kamar per `kelas` (`kamar.statusdata='1'`, terisi = status ≠ `KOSONG`, tarif = `MIN(trf_kamar)`, `mulai Rp` bila beda) dari DB SIMRS (hanya baca, `app/server/functions/display-kamar.ts`, `getDisplayKamarAction`). Poll 60 detik, gagal → data terakhir + chip `TERAKHIR HH:mm`, backoff ×2 s/d 5 menit; ganti hari WITA → refetch. Jadwal satu baris per dokter + poli (`mergeJadwal`, kunci `kd_dokter`+`kd_poli`): dokter 2 sesi (pagi & sore) → `JadwalRow.sesi[]` (urut jam, slot identik sekali), label poli lewat `poliLabel` (`app/lib/poli-call.ts`, sama dengan `/display-poli`: THT-KL tetap huruf besar), jam praktek ditumpuk per sesi di kolom JAM PRAKTEK (ukuran font sama dengan 1 sesi, baris memanjang). Nama dokter tampil lengkap (wrap, tanpa truncate); baris `min-h-[76px]` tumbuh mengikuti isi. Status baris (praktik/terjadwal/selesai, `jadwalStatus` per sesi: di antara sesi = terjadwal) dihitung client tiap 30 detik; semua jadwal satu halaman tanpa paging (baris min 76px; ≥ 13 jadwal → font compact `COMPACT_FROM`). `DisplayTopBar` prop `eyebrow`, `KioskRunningText` prop `label`/`icon`. Kanvas `useDisplayFill` (`useDisplayScale.ts`): skala sama dengan `/display` tapi lebar/tinggi kanvas mengikuti viewport (tanpa bar hitam di jendela non-16:9); `/display` tetap `useDisplayScale` (letterbox). Teks di `/display-kamar` (`DisplayJadwalTable`, `DisplayKamarList`, `DisplayTopBar` — header juga dipakai `/display` & `/display-poli`) memakai `text-bp-ink` (hitam), jangan `text-bp-muted`/`text-bp-faint`; baris SELESAI dibedakan lewat latar `bg-bp-surface-2` + label. Judul kolom tabel (NO/NAMA DOKTER/…) 18px bold, baris judul 56px. Label status (SEDANG PRAKTIK/TERJADWAL/SELESAI) 20px bold (compact 17px), kolom STATUS 250px (header & baris harus sama lebar).
- `/display-poli` (publik, **mode uji**, pengganti `samples/antrian_poli`, desain `design/DESIGN-DISPLAY-POLI.md` **Alternatif B** §10.2): panggilan poli dari SIMRS `antripoli` (Khanza: satu baris per dokter+poli, tanpa kolom waktu, status `1` dipanggil, display PHP lama menandai `2` lalu `3`). **Hanya baca** SIMRS, supaya display PHP lama tetap jalan. Server (`app/server/functions/display-poli.ts`) membaca `antripoli` maks 1×/detik (dibagi semua TV), `createPoliCallDetector`: `no_rawat` baru status 1/2/3 = panggilan baru (status 3 ikut dihitung: display PHP lama tiap 2 detik mengubah baris terpilih `1→2` dan semua `2` lain `→3`, jadi saat beberapa poli memanggil bersamaan sebuah panggilan bisa lewat `1→2→3` di antara dua snapshot dan dulu hilang tanpa suara di `/display-poli`), `no_rawat` sama kembali ke `1` (atau `3→2`) = panggil ulang; snapshot pertama setelah server start hanya seeding (snapshot di memori). Tiap panggilan dicatat ke tabel app `poli_calls` (migration `0019`: nomor, pasien, poli, dokter, `is_recall`, `called_at`, `finished_at` = saat dokter+poli yang sama memanggil pasien berikutnya); TV poll `getDisplayPoliAction({ afterId })` tiap 2 detik dari tabel ini, jadi nama terakhir per poli tetap ada setelah restart. Batas hari = WITA eksplisit (`dayRange`, `+08:00`, drizzle menyimpan DATETIME UTC). Hanya pasien `reg_periksa.tgl_registrasi` hari ini, poli `EXCLUDED_POLI` dikecualikan. Nomor `kd_poli + no_reg` (`PM013`), nama tanpa gelar & huruf berspasi dirapatkan (`cleanPatientName`), label poli title case (`poliLabel`), TTS "Nomor antrian PM 13. Atas nama X. Silahkan menuju ke ruang Y." (`poliCallText`, `app/lib/poli-call.ts`: dg→daeng, st→siti, hj→hajjah, h.→haji, THT-KL→THT-KAEL). Layout Alt B: video + kolom kanan 640 hanya `DisplayPoliCallPanel`, `DisplayPoliStrip` (tile per poli jadwal hari ini, urut jadwal, 7 tile/halaman, ganti 10 detik, loncat ke poli yang dipanggil) di atas running text; `useDisplayFill`; `useCallAnnouncer<T>(textOf)` dipakai bersama `/display`. Tombol "🔊 Tes panggilan poli" (Pengaturan, `DisplayCallTest target="poli"`, `testPoliCallAction`) → slot tes sendiri di memori (`requestPoliDisplayTest`, terpisah dari tes `/display`) → `getDisplayPoliAction.test`; tiap `/display-poli` terbuka memutar contoh `PU001 · TES PANGGILAN · Poli Umum` (id negatif, tidak dicatat). Reload/buka halaman tidak mengulang panggilan lama (`afterId`), kecuali panggilan terakhir < 20 detik (`REPLAY_RECENT_MS`, umur dihitung jam server `lastCallAgeMs`) diumumkan sekali lagi agar reload tak sengaja tidak memotong panggilan. Riwayat di `/admin/riwayat-poli` (semua role, `listPoliCallsAction`, filter tanggal & poli, refresh 30 detik untuk hari ini). Deploy: jalankan `make db-migrate-raw` (tabel belum ada → `/display-poli` kosong). Mode tulis status (klaim `1→2`, `2→3`) belum dibuat: tambahkan setelah display PHP lama dimatikan.
- `/display-poli-mata` (publik, desain `design/DESIGN-DISPLAY-POLI-MATA.md`, pengganti SIMRS `webapps/jadwaloperasi.php` + `data_operasi.php`): video + kolom 720 `DisplayPoliMataPanel` (panggilan terakhir Poli Mata + 3 pasien yang dipanggil sebelumnya dari `poli_calls`, terbaru dulu, satu baris per pasien, berlabel "Sudah terlayani" — `getPoliMataCalled`; bukan antrean berikutnya) + `DisplayOperasiStrip` (jadwal `booking_operasi` hari ini, ruang `OPERASI_RUANG` = `O1` OK MATA, query sama dengan `data_operasi.php` tanpa nama pasien, cache server 5 detik, 5 tile/halaman ganti 10 detik, loncat ke halaman tile *Proses Operasi*/*Menunggu* terdekat, tile berkedip saat status berubah tanpa suara). Server `app/server/functions/display-poli-mata.ts` (`POLI_MATA_KD = "PM"`, `formatOpRow`: jam `HH:MM`, `jam_selesai` ≤ mulai disembunyikan, status `NULL` = Menunggu, kata kapital penuh → title case kecuali isi kurung), action `getDisplayPoliMataAction`.
